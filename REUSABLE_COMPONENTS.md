# ParaSpace — Reusable Components Registry

Single source-of-truth catalog of reusable orchestrators, handlers, UI/dialog builders, matchers, and utilities across `@para-space/core`, `@para-space-dev/cli`, and `para-space-vscode` ([D-050](DECISIONS.md)).

**Purpose:** Prevent duplicate implementations across the monorepo. Contributors and AI coding agents must consult this registry before introducing any new helper, command handler, prompt flow, or workspace/worktree matcher.

---

## Update Protocol

1. **Check before writing:** Before writing any new helper, command flow, prompt, validator, or matcher in `core`, `cli`, or `vscode-extension`, search this file (`REUSABLE_COMPONENTS.md`) first and reuse or compose existing building blocks.
2. **Place shared logic in the right layer:**
   - Cross-package domain orchestration, multi-repo provisioning/cascade removal, workspace file I/O, query filtering, git operations, and state persistence belong in `@para-space/core`.
   - Package-specific interactive prompts, terminal/VS Code command actions, and MCP/LM tool handlers belong in dedicated helper modules (`*Prompts.ts`, `*Actions.ts`, `*Handlers.ts`) under less than **250 lines** per file ([GUIDELINES.md §2.1–2.3](GUIDELINES.md)).
3. **Update in the same commit:** Whenever a reusable function, handler, strategy, or UI component is added, moved, or has its signature changed, update `REUSABLE_COMPONENTS.md` in the **same commit** with:
   - **Module path** (relative link to the source file)
   - **Exported symbol & signature** (parameters and return summary)
   - **Responsibility** (single-purpose summary)
   - **When to reuse** (usage context and callers)
